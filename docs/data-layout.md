# 三游戏工作区与 data 结构

当前源码支持原神（genshin）、绝区零（zzz）、崩坏：星穹铁道（hsr），模组来源均为 GameBanana。

三个游戏使用同一套安装、启用、皮肤模组、预览图、更新检查、搭配方案和通知实现。差异集中在 `src/core/games.cjs`：游戏编号、分类编号、加载器名称、图标和默认背景。以后修复公共规则会同时作用于三个工作区。

## 文件结构

原神旧数据原址保留，避免移动已安装模组后破坏现有启用链接。新增游戏的状态和下载记录放入 `games`，安装副本仍统一位于 `library`。

```text
data/
├── workspaces.json                 当前选中的游戏，重启恢复
├── state.json                      原神模组、方案、分类、设置；全局偏好的权威记录
├── taxonomy.json / categories.json  原神分类缓存（用到时生成）
├── download-queue.json              原神下载队列
├── downloads/                      原神下载包、record.json 与临时解压内容
├── deployment-journal.json          原神启用操作恢复记录（操作期间存在）
├── games/
│   ├── zzz/
│   │   ├── state.json              绝区零模组、方案、分类与游戏设置
│   │   ├── taxonomy.json / categories.json
│   │   ├── download-queue.json
│   │   ├── downloads/
│   │   └── deployment-journal.json  操作期间存在
│   └── hsr/                        与 zzz 相同，内容完全独立
├── library/
│   ├── <原神原有分类与模组目录>      保持旧位置
│   ├── zzz/<分类>/<模组>/           绝区零安装副本
│   └── hsr/<分类>/<模组>/           星穹铁道安装副本
├── previews/                       共用图片存储，模组各自记录自己的图片地址
├── home-background-<游戏ID>.jpg     用户选择的背景
├── home-background-<游戏ID>.webp    获取的官方背景
├── backgrounds/<游戏ID>/           新背景缓存（按需生成）
│   ├── current.json               当前背景类型、来源地址与版本目录
│   └── <版本目录>/
│       ├── poster                 静态背景或视频封面
│       └── video.webm             仅官方提供视频时存在
├── notifications.json              共用通知历史，消息标注来源游戏
├── components/                     旧版本可能遗留的组件文件（新版不再下载或使用）
├── session/                        共用 Chromium 会话；启动清理界面缓存
└── logs/errors.log                 共用错误日志
```

文件按需生成；首次未进行相关操作时部分缓存、下载和恢复记录不存在。旧 `home-background.jpg` / `home-background.webp` 仅作为原神背景兼容读取。内置默认背景打包在程序资源中，不需要复制到 data。

新获取的官方背景与自选图片保存到 `backgrounds/<游戏ID>`。完整下载成功后切换 `current.json`，再删除该游戏之前的背景目录与旧 JPG/WebP 缓存；下载失败保留原背景。视频和封面都在本地，离线可用。游戏设置新增独立的 `autoBackground` 开关，缺省关闭；开启后每次启动检查，来源未变且本地文件完整时不重复下载。关闭开关不会删除已保存的背景。

## 设置与行为

- **游戏独立**：加载器 Mods 路径、外部 EXE、背景；已安装模组、启用状态、预览图关联、热键记录、方案、忽略更新记录、下载队列、分类缓存也独立。
- **全局共用**：代理、界面偏好、自动启用、自动检查、NSFW 模糊和链接/复制部署方式等。通过任意游戏修改后，其余工作区立即读取相同偏好。为兼容旧版本，权威记录仍在原神 `state.json.settings`。
- **切换不改变启用状态**：切换游戏不会停用其他游戏的模组；后台任务仍写入发起它的工作区。通知中的下载/更新入口返回来源游戏。
- **加载器要求**：原神选择 GIMI、绝区零选择 ZZMI、崩坏：星穹铁道选择 SRMI；文件夹必须含 `d3dx.ini`，程序使用其 `Mods` 子目录。程序不下载、配置或启动 XXMI。
- **启用目录隔离**：不同游戏不能配置相同或相互嵌套的 Mods 目录。程序数据目录不可作为启用库；旧版本 `components` 中已有的对应加载器目录只保留严格兼容例外。
- **统一启用规则**：同一角色最多一个普通模组，皮肤模组可同时启用任意多个。三个游戏共同使用该规则。

新增工作区不移动旧原神安装副本，也不清除手动模组。备份建议完整复制 data，并另行备份位于 data 外的各游戏加载器目录。
