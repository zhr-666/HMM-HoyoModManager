# 0.9.5 更新启动修复

用户诊断确认 0.9.2 下载的 0.9.3 更新包包含 exe 和 app.asar，PowerShell 5.1 可用、脚本语法检查通过，但不存在 helper.lock、ready、status.txt 或 update.log。现有证据只能定位到助手未开始安装，无法确认 Windows 进程启动失败的具体原因。

改动：启动时将标准输出和错误写入 helper-startup.log；捕获进程启动失败和提前退出；等待上限由 10 秒调整到 60 秒；使用隐藏的普通子进程，准备完成后解除引用；助手确认就绪后才记录更新交接。旧记录缺少状态、备份为空且暂存包和替换清单完整时允许重试。真正开始替换的更新仍走恢复流程。旧包版本不高于当前版本时不允许降级。

此修复需要先放进正在运行的软件，旧版失败的更新器无法自行获得它。退出软件后，将完整 Windows 压缩包内的程序文件覆盖到原软件目录，保留原 data、GIMI 和 Mods 目录。不要删除旧目录，也不要只替换 exe。用户配置及模组路径不会因程序文件覆盖而迁移。

验证范围：Node 回归测试、受控更新界面测试、Windows 包资源检查，以及 Electron 下真实 ZIP 准备流程和配置保留检查。macOS 无法验证 Windows PowerShell 子进程的实际退出、替换和重新启动；该部分需 Windows 实机确认。
