# Windows 实机验收

## 三游戏工作区（Windows 实机待验收）

- 原神、绝区零、崩坏：星穹铁道分别显示 GIMI、ZZMI、SRMI 文件夹选择；所选根目录需包含 `d3dx.ini`，程序固定管理其 `Mods` 子目录。
- 程序没有 XXMI 下载、配置、启动或自动探测入口；外部 EXE 仍只在用户明确点击「打开程序」时启动且不附加参数。
- 三个游戏的安装库、启用状态、方案、下载、分类和游戏设置互不串用；切换或重启不改变其他游戏的启用状态。
- 相同路径或相互嵌套的 Mods 目录不能分配给不同游戏；三个启用库中的手动文件都不得删除或覆盖。
- 每个游戏分别验证普通模组单选、皮肤模组任意多选，并验证修改统一规则后三个工作区同时生效。
- 按 [data 目录说明](data-layout.md) 核对旧原神数据未移动，绝区零和星穹铁道新增目录正确。

## 鸣潮与游戏列表（Windows 实机待验收）

- 全新数据目录首次启动：首页内容区是纯灰背景，没有游戏背景图、Logo、信息卡或按钮；左侧无游戏图标，`data/games` 下无游戏目录；「全部游戏」展示四款游戏。
- 依次单击原神、鸣潮、绝区零：每次进入所选游戏首页，仅创建所选游戏的 `data/games/<游戏 ID>`；最新添加的图标位于左侧最下方。双击图标仍进入对应工作空间。
- 鸣潮工作空间使用 GameBanana 游戏 ID `20357` 的分类与列表，设置页可选择 WWMI Mods。下载、导入、启用、停用、方案和预览与其他游戏隔离。
- 鸣潮游戏设置里的「获取官方最新背景」可从库洛启动器取得当前图片；断网或官方接口失败时，原背景保持不变。启用自动更新背景后重启再确认。
- 从首页下方点击「管理我的模组」「管理搭配方案」：游戏图标飞向工作空间左栏，分别落到相应页面。
- 在首页左栏右键鸣潮图标，核对删除提示并取消一次，确认没有文件变化；再次确认移除，检查 `data/games/wuwa` 与已配置 WWMI Mods 下的 `HoYoModManaged` 均删除，其他手动 Mods 文件和其他游戏数据保留。
- 将非本程序管理的同名 `HoYoModManaged` 放到测试 Mods 目录，确认移除被拒绝且数据未删除。关闭并重新启动，检查旧用户已有游戏仍在左栏、未添加的鸣潮目录不被预建。

## 1.1.6 本地导入不做前置检查（Windows 实机待验收）

- 导入一个包内引用了外部命名空间（例如 `run = CommandList\TexFx\...` 而本包没有 `namespace = TexFx`）的本地压缩包：选完压缩包与分类后**直接完成导入，不弹「前置模组提醒」**，也不会被中止。
- 导入完成后在「我的模组」里把这条模组关掉再打开：**同样不弹前置提醒**，直接启用；这条模组照旧进 `GIMI\Mods\HoYoModManaged\<模组 ID>`。
- 对照：从工坊下载一个 Requirements 未满足的模组，**下载前仍弹前置提醒**；开启「下载后自动启用」时，下载完成后的自动启用也会再核对一次；应用搭配方案时同样核对。
- 1.1.5 的导入分类验收项（选分类、按分类落库、不再新建「本地导入」）在本版包里一并复验。
- 从工坊安装一个带预览图的模组：安装成功后程序目录 `data\games\<游戏 ID>\previews` 下出现对应图片；关闭网络再打开「我的模组」，列表仍能直接显示预览图，不应再次请求 GameBanana 图片。更新该模组后应使用新的本地预览图，旧缓存可以被清理。

## 1.1.5 导入本地模组按所选分类落库（Windows 实机待验收）

导入本地模组（① 选压缩包 → ② 选分类 → ③ 导入）：

- 点「导入本地模组」→ 选压缩包 → 弹出「选择分类」窗口：按 GameBanana 分类逐层进入（大分类 → 子分类/角色），**任意一层都能导入**：停在总分类上时模组直接放进大分类，不必选到最小子分类；当前层级可搜索，面包屑可回退；确认按钮显示「导入到「<分类名>」」；确认时**只弹出一次系统文件选择器**，不再出现「选择 Mods 内的安装文件夹」窗口。
- 导入完成后模组出现在「我的模组」**所选分类的位置**（例如选「Skins / Characters / 甘雨」就归到甘雨下，选「Skins」就直接挂在 Skins 下），**绝不会新建一个「本地导入」总分类**；安装库里的副本在 `data\games\<游戏 ID>\library` 下对应的分类文件夹（`总分类-哈希[\角色-哈希]`），并自动启用 —— `GIMI\Mods\HoYoModManaged\<模组 ID>` 里出现该模组（与其他模组同一条启用规则），不需要用户选择文件夹。
- 导入到角色分类的本地模组与工坊下载的模组同等对待：同一角色只能启用一个（互斥），分类、启用/停用、检查更新、热键、重命名、移除都按「我的模组」的规则走。
- 选择分类期间重复点「导入本地模组」不会再弹第二个文件选择器；点「取消」或按 ESC 关闭分类窗口则整个导入中止，不会落库，也不会有任何临时文件留在安装库。

## 1.1.4 通知最上层、导入两步与工坊翻页回顶（Windows 实机待验收）

通知的图层与位置（重点：**位置不变，只是画在最上层**）：

- 右下角通知弹窗、通知中心悬浮按钮与展开的面板都停留在原来的右下角位置，不因为本改动移动。
- 打开任意对话框（例如模组详情、更新结果窗口）：右下角通知与通知中心仍清晰显示在对话框与遮罩之上，不会被盖住、也不会被遮罩的模糊糊掉；关掉对话框后位置不变。
- 通知全部收完（弹窗消失、面板收起）后，右下角按钮区域可以正常点击，不会挡住页面上的操作。

8 秒自动关闭：

- 完成一次下载或检查更新，右下角弹出完成通知：8 秒内它一直在，这期间点「×」能立刻关掉；不点它，8 秒后自己消失。
- 自动消失后打开通知中心，那条消息仍在列表里，未读角标不掉；点它仍能跳到对应页面。
- 3 秒即时通知（「已加入下载列表」等）仍是 3 秒，不受影响。

下载任务卡：

- 排 2 个以上下载：任务卡上「正在下载第 X 个，共 X 个」只有文字，没有整批的进度条与百分比；当前文件一行仍有进度条与百分比，并随下载推进。

模组工坊翻页：

- 滚到页面下方，点「下一页」或「上一页」：新页面加载时页面立刻回到最上方，不保留上一页的滚动位置。
- 翻页时断网：页面同样回到最上方，并给出加载失败提示。

导入本地模组（两步）：

- 1.1.4 的实现漏掉了「选分类」这一步（压缩包不带分类交给本机库，模组会落进新建的「本地导入」总分类）：**导入的验收项改到上面的 1.1.5**，本节按 1.1.5 的步骤执行。

## 1.1.3 通知系统统一、取消下载、后台任务、忽略版本、游戏级设置与界面整理（Windows 实机待验收）

通知系统（只保留三种通知状态，见 [通知系统统一规范](superpowers/specs/2026-09-19-notification-unification.md)）：

- 点「下载 Mod」：右下角立刻弹一条「已加入下载列表」，3 秒后自动消失；没有关闭按钮、点不动、不进通知中心；下载过程中不再出现其它 Toast。
- 打开通知中心：下载任务只有**一张**卡，同一张卡里既有「当前文件：<文件名> · N%」与当前文件的进度条，也有「正在下载第 X 个，共 X 个」与整个队列的进度条，不是两个独立任务。
- 队列里排 3 个下载：卡片上的「第 X 个」跟着当前任务走，总体进度在当前任务内部也平滑前进，不跳变。
- 全部下载结束：右下角弹「全部任务下载完成」，8 秒后自动关闭（1.1.4 起）；点「×」可以提前关掉，之后打开通知中心仍能看到这条消息；点这条通知跳到「下载列表」。
- 有下载失败时：完成通知里写明成功与失败数量，并提示可在下载列表重试。
- 点「检查更新」：开始时不弹右下角通知；通知中心的卡片显示「正在检查更新第 X 个，共 X 个」与进度条；检查更新没有任务页面，卡片不可点击、鼠标不是手型；结束后弹「检查更新完成：…」（8 秒后自动关闭），关掉后进通知中心，点它能打开更新结果窗口。
- 进行中的任务不再主动弹窗：任务开始、进行、结束的任一时刻，右下角都不会出现带「知道了」的任务弹窗；状态与进度只在通知中心的「进行中的任务」里看。
- 有对应页面的任务卡（下载 → 下载列表，软件更新 → 设置里的软件更新卡片）点击后直接跳过去；没有页面的任务卡（检查更新、替换 Hash）不可点击、没有手型。
- 切换软件更新（检查、下载、校验）时：点「检查软件更新」开始时不弹通知，点「下载更新」仍弹「开始下载更新」作为即时反馈；进行中只在通知中心的任务卡上看进度（卡片可点进设置里的软件更新卡片），状态落到「发现新版本 / 已是最新 / 已准备好」时补一条通知（8 秒后自动关闭）。
- 其它按钮的成功反馈（忽略版本、更新官方背景、替换 Hash 完成、导入结果、必填校验）都是 3 秒即时通知，不进通知中心；操作失败仍是一条常驻错误通知，关掉后能在通知中心查到，并可展开「查看详细信息」。
- 旧提示不能与新的并存：右下角不会再出现任务卡，页面上也不再有小弹窗式的下载提示。

只保留深色模式：

- 设置页里没有「外观主题」这一项，界面、窗口底色、标题栏按钮全程深色；系统切成浅色也不会有浅色界面。
- 从 1.1.2 或更早升级（`data/state.json` 里有 `theme`）后启动：界面是深色，设置文件里的 `theme` 字段被丢弃，不影响其它设置与已启用模组。

取消下载与后台任务：

- 下载一个大文件，在「下载列表」点「取消下载」：下载立刻停止、`.part` 临时文件被清掉、状态显示「已取消」而不是「失败」。取消后可以重试，重试会重新下载。
- 下载进行中，打开通知中心点下载任务卡上的「取消」：能停下当前这一行，队列里的下一个任务继续。
- 点「检查更新」的任务卡：结束后卡片消失（它不再是「进行中」），由那条完成通知接手。

通知中心：

- 悬浮按钮「×」关闭右下角通知后，打开通知中心仍能看到那条消息（不是删除）。
- 通知中心里的消息可点击时鼠标变成手型、悬浮有轻微背景变化；没有对应页面的消息既不绑点击也没有手型。
- 面板右上角只有两个按钮：「×」＝关闭通知中心小窗（消息一条都不删，重新打开还在）、双勾「清空消息」＝清空所有消息（列表回到空状态、角标清零，磁盘历史同步清空；进行中的任务不受影响）。
- 单条消息右侧的「×」只删这一条，其它消息不受影响。
- 点消息按钮时面板从右下角按钮位置展开成完整面板，关闭时反向收回。
- 没有进行中的任务时，「进行中的任务」整块（含标题）不显示。

忽略更新：

- 检查更新发现新版本 → 在结果窗口点「忽略这个版本」→ 再次检查时该版本不再提示。
- 作者之后上传更新的文件后，检查更新会重新提示。
- 在「我的模组」右键该模组，菜单里出现「已忽略版本：1 个」，点开能看到版本列表并「取消忽略」；取消后下一次检查重新提示该版本。

界面整理：

- 进入工作区与返回首页时：动画过程中画面上只有一个 Logo（目标位置的 Logo 与它所在方块的底色都不提前显示，落点上不会立着一块空方块），返回时沿原路径反向飞回（方向与进入相反）。
- 飞行动画约 0.7 秒、全程都在移动（不是一下子窜到终点再停住），最后一帧与目标 Logo 完全重合后交接：看不出闪动，落点不偏、也不会飞出行栏外；从「全部游戏」的 104px 大图标进入时图标会一路缩到左栏的 44px。
- 连点/双击不会同时出现两个飞行的 Logo。
- 「全部游戏」页是大图标网格，每个游戏仅显示方形图标和下方名称，没有状态文字或游戏设置区；绝区零与崩坏：星穹铁道图标底部使用中国服的 miHoYo 字样。
- 游戏 Logo 悬浮提示统一为「双击进入模组工作空间」。
- 「我的模组」右键菜单显示「安装库 / 启用库」；「替换 Hash」在「检查更新」左边。
- 详情页顶部图片区高度固定，图片后加载不会把内容顶下去；多张图片时可点缩略图切换大图，鼠标停在大图上滚轮切上一张/下一张，大图整张完整显示、不被裁切；鼠标停在缩略图条上滚轮横向滚动缩略图，滚到两端停住。
- 滚轮不会穿透层级：详情窗口（二级）滚动不会带动工坊页面（一级）滚动，窗口里的分类列表、缩略图条（三级）滚动也不会带动窗口滚动；对话框打开期间背后的页面不滚动。
- 详情页「选择要安装的文件」条目更紧凑，一屏能看到更多文件。
- 模组工坊的卡片没有「查看详情」按钮：点卡片任意位置都能打开详情；卡片里的「在 GameBanana 查看」仍只打开网页，NSFW 封面第一次点击先揭开遮罩。卡片比过去更矮，方块之间更紧凑。
- 在详情介绍里选中文字右键 → 菜单「设置为热键提示」就在鼠标位置显示（不会被详情窗口盖住），点它之后「查看热键」顶部显示这段文字，重启后仍在，且不同模组互不串。
- 查看热键：顶部是热键提示，下面是紧凑卡片网格（按键、反切键、类型、来源、DISABLED），不再有「全部热键」「生效条件」和 0/1 指令；标题是「热键」而不是「自定义热键」。
- 页面上不再出现任何横条提示；成功反馈是右下角 3 秒即时通知，失败是必须手动关闭的常驻通知。
- 错误提示第一行是通俗中文（例如「找不到指定文件…」），需要时展开「查看详细信息」看原始英文。

设置拆分：

- 左下角齿轮 = 设置页（当前游戏设置、软件更新、启动时检查、自动启用/检查、窗口材质、网络代理、维护与诊断）。
- 首页右下角「打开程序」右边（也是游戏 Logo 区的右下角）的齿轮 = 当前游戏设置：点开在原地弹出「<游戏名> · 当前游戏设置」窗口（GIMI / ZZMI / SRMI 文件夹、外部程序、启动器背景），不切换页面；窗口标题写明是哪个游戏。
- 齿轮位置与「打开程序」同一排、紧挨着通知按钮左侧，三个按钮等高对齐。
- 从 1.1.2 升级：原来的 GIMI 路径、外部程序与背景出现在《原神》的游戏设置里；切到其他游戏时这三项为空，各自选择后互不影响（原神换背景不会改到别的游戏）。
- 切换游戏后首页背景、游戏设置页显示的值都跟着该游戏变化。

更新完成后的磁盘清理：

- 完成一次自动更新（旧版 → 新版）后启动新版：程序目录里的 `.hoyo-updates` 不再保留该次任务目录，原下载 ZIP、`staging` 与 `backup` 一并删除；`data`、GIMI、启用状态与界面资源不受影响。删除在后台进行，启动不被明显拖慢。
- 关闭自动更新窗口：点「软件更新 → 下载更新」进入「已准备好，重启后完成更新」后不重启，关闭程序再打开：`staging` 仍在（可以继续点「重启并安装」），但原 ZIP 已经不存在。
- 下载更新中途断网或校验失败：`.hoyo-updates` 下不残留半成品任务目录。
- 手动删除 `.hoyo-updates` 后再启动：设置里的软件更新显示空闲，不再出现「上次软件更新未完成，请恢复旧版本后重试」，检查与下载都可用。
- 模组安装完成后：`data/games/<游戏 ID>/downloads/<来源-文件>/` 里只剩 `record.json`，`package.zip` 已删除，下载行提示「安装包已清理」；失败任务保留下载包，重试确实不重新下载。
- 「下载」页点「清理安装包」：此前遗留的安装包被删除，提示释放的空间大小；模组本体与下载记录不变，重试会重新下载。

本地导入（两步流程见 1.1.4）：

- 点「导入本地模组」→ 选压缩包 → 选安装库分类 → 确认：只弹出一次系统文件选择器，导入结束后模组出现在「我的模组」，不会再次弹出选压缩包的窗口，也不再询问 Mods 内的安装文件夹。
- 选择安装库位置期间重复点「导入本地模组」不会再弹第二个文件选择器。

## 1.1.2 后台检查更新、界面资源不缓存与启动器细节（Windows 实机待验收）

后台检查更新：

- 「我的模组」与「设置 → 维护与诊断」两处点「检查更新」：页面上方不再出现全局进度条；开始时不弹通知，检查结束后再出现一条常驻的「检查更新完成」通知。
- 检查期间界面不锁死，可以继续翻页、下载或安装；连点「检查更新」不会重复发起。
- 检查结束后**不会**自动弹出结果窗口；「检查更新」按钮右上角出现红点（两个入口同时亮）。
