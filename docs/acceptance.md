# Windows 实机验收

## 0.9.2 更新资源校验

- 0.9.0 / 0.9.1 首次升级需退出程序，将新版完整解压覆盖原程序目录，保留 data 和 GIMI 及个人文件。确认版本显示 0.9.2。
- 后续有更高版本时，检查、下载后能进入“重启并更新”，不再误报缺少程序资源。
- 准备阶段不改变原程序、data 和 GIMI；真正的资源缺失、资源被替换成目录或链接时仍拒绝更新。
- 自动化验证已增加真实 Electron ASAR 和完整 ZIP；Windows 助手替换、重启仍需实机验证。

## 0.9.1 前置与界面验收

- 从 0.9.0 设置中检查软件更新，下载 0.9.1，点击重启更新；重启后确认版本、模组名称、启用状态、搭配和路径不变。
- 仅声明 3DMigoto / GIMI 的模组不弹缺失提醒；同时缺少 TexFx 等前置时，仍显示对应前置。
- 前置弹窗跟随浅色/深色主题；取消、右上角关闭、Escape 均不继续原操作。
- GameBanana 前置在软件内打开详情，可选择下载；原操作取消，原模组未被误启用。
- GitHub 前置用浏览器打开原网址，提醒窗口保留，由用户手动安装；程序不自动下载或执行项目。
- 首页、我的模组、搭配方案、下载列表的标题不带问号；本机模组及小搭配标题移除；模组工坊说明在标题下方直接显示。
- 二级弹窗的问号紧跟标题或相关文字，悬停与键盘聚焦均能看到说明。

## 0.9.0 软件更新验收

- GitHub 最新稳定版高于当前版本才提示，同版本/旧版本/预发布不提示升级；缺少包或校验值时不安装。
- 默认启动只检查不下载，开关关闭后不自动检查；手动检查显示版本和更新说明。
- 点击下载显示进度，断网/校验失败保留原程序与 data；下载成功仍等待“重启并更新”。
- 有模组任务或修改时拒绝重启；空闲时启动内置助手、退出软件、替换程序后重启。
- 更新前后对比 data/state.json、全部模组源文件和 GIMI Mods 内容，更新助手不修改它们；重开后名称、启用状态、方案、路径和背景保持。
- 路径包含中文、空格、括号、&、[ ] 时，助手使用字面路径正确替换。
- 注入文件锁/磁盘写入失败，旧程序恢复或保留可恢复的备份和日志；模拟断电后通过 HoYoMod-Recover.cmd 恢复。
- 实测新程序重启后显示新版本。以上 Windows 助手项目尚需 Windows 实机验证，不能用 macOS 单元测试替代。

## 初次使用
- 完整解压，双击 HoYoMod.exe，中文窗口正常显示；关闭重开后设置保留。
- 选择已有 GIMI 文件夹，自动连接 Mods；不要求 XXMI。
- 识别 GIMI Mods 路径；错误路径有说明，不覆盖原有 Mod。
- 网络不可用时本地库仍能使用，在线页面有重试说明。

## 批量替换 Hash
- 预览时文件不变，列表显示所有命中模组、文件、次数。
- 执行后启用与未启用模组都替换，游戏加载目录中的启用副本同步。
- 重启后替换记录仍在，可按批次回滚，确认原文件恢复。
- 修改文件后再回滚会停止，不覆盖后来的编辑；部署失败后原版本保留。

## 自定义热键
- 安装含多层目录与 Key 配置的模组，打开“查看热键”，确认组合键、反向切换键及来源行号。
- 查看前后 `.ini` 内容一致；旧模组可补扫，更新后热键同步变化。
- 游戏中满足配置条件时验证作者定义的按键；扫描仅展示配置，不执行或推断效果。

## Mod 工作流
- 按角色浏览、搜索、翻页，查看作者预览与文件选项。
- 选择一个兼容当前原神版本的普通外观 Mod，下载、安装、启用。
- 启用同角色另一个 Mod 后，GIMI/Mods/HoYoModManaged 中只有新条目；两个不同角色可以同时存在。
- 使用外部加载器启动游戏，确认所选外观生效。
- 管理器只保存部署文件；游戏中刷新由外部加载器处理。
- 保存组合、全部停用、应用组合，验证游戏与本地部署一致。

## 更新、错误和便携
- 默认下载不启用；开启自动启用后下载即切换。
- 自动检查只提示；手动安装更新后保留启用状态和方案引用。
- 切换三种排序和 SFW/NSFW 勾选；NSFW 图片默认模糊，点击显示，设置开关生效。
- 下载记录保留网址与文件上传日期；安装失败后查看原因并重试缓存。
- 检查结束汇总全部更新、失败及未知项；最新 72 小时内的文件全部列出，不自动选择。
- 遇到多文件更新明确选择；断网/损坏包后旧版本仍可使用。
- ZIP、7Z、RAR 中的 DLL、EXE、Python 等文件原样安装，不由管理器执行；路径穿越、链接和异常解压大小仍拒绝。
- 关闭软件，移动完整便携目录后重开，库正常；内部组件与外部路径按界面提示重新设置。
