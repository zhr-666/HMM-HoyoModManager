# 鸣潮与游戏列表管理实施计划

**目标：** 接入鸣潮，并让工作空间随用户添加、移除游戏而创建和清理。

**依据：** `docs/superpowers/specs/2026-09-24-wuwa-game-management.md`

1. 扩展游戏注册和静态资源：GameBanana 分类、WWMI、鸣潮图标/Logo/背景；同步界面资源白名单与来源说明。
2. 在工作空间层保存已添加游戏顺序；首次启动不初始化未添加游戏；从旧游戏目录推导既有列表；添加时初始化，失败时不登记。
3. 实现移除流程：拒绝繁忙任务，使用现有停用事务清理部署；校验 HoYoModManaged 归属后删除，随后删除游戏数据并更新登记。失败保留可重试状态。
4. 主进程与界面接入添加/移除动作，左栏按添加顺序显示，右键确认提示；双击和底部管理按钮复用工作空间飞行动画。
5. 扩展分类中文显示至大分类及模组记录；保持标识与磁盘路径不变。
6. 添加业务与失败路径回归测试，运行专项测试、`pnpm check`、`tests/ui-assets.test.cjs` 和可运行的界面脚本；审查差异，只提交本任务文件。
