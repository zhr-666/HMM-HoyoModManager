# HoYoMod 1.0.0 Implementation Plan

**Goal:** 彻底修掉“更新助手提前退出（退出码 0）”，在真实 Windows 上取得证据后交付 1.0.0。
**Architecture:** 更新引擎由 PowerShell 改为程序自身以 `ELECTRON_RUN_AS_NODE` 运行的 `update-run.cjs`（GUI 子系统宿主，不需要控制台）；启动器以 `started.txt` 心跳判定引擎是否真的启动，并保留 `conhost --headless` + PowerShell 作为第二引擎。
**Tech Stack:** Electron 主进程、Node 文件系统、Windows 进程启动语义、GitHub Actions（Windows/macOS）。

依据：[根因与修复方案](../specs/2026-09-17-detached-helper-console.md)。

## Task 1：引擎 `src/core/update-run.cjs`

自包含 Node 程序，`--plan <plan.json> [--token <t>] [--recover-only]`。

- 第一件事写 `started.txt`（token）与 `update.log` 首行，随后取 PID 锁 `helper.lock`。
- 校验：工作区必须在 `.hoyo-updates` 内、`staging` 必须等于 `<job>/staging`、条目必须在允许清单内且不重名、不得与 `data`/`.hoyo-updates`/受保护路径重叠、不得含链接、必须同时含 `HoYoMod.exe` 与 `resources`。
- 写 `ready` 后等待 `plan.parentPid` 退出（上限 60s），再按条目 `target→backup`、`staging→target` 搬迁，失败即回滚并重启旧程序；`--recover-only` 只回滚。
- 结束写 `status.txt`（`updating`/`complete`/`rolledback`）并启动 `HoYoMod.exe`。

## Task 2：启动器 `src/core/update-helper.cjs`

- `helperAttempts()` 目前只生成一个引擎：应用 Node 宿主（`conhost --headless` 兜底已被真实 Windows 证伪，见 spec）。
- `startHelper()` 按引擎顺序启动，每个引擎先在启动窗口内等心跳；心跳出现后只等 `ready`；宿主提前退出或没有心跳则记录诊断并换下一个引擎。
- 保留 `helper-startup.log` 与“更新助手提前退出（退出码 X，信号 Y）”“更新助手启动超时”“启动日志：<路径>”等既有文案。

## Task 3：交接与恢复 `src/core/app-update.cjs`、`src/core/app-update.ps1`

- `_installHelpers()` 把 `update-run.cjs` 与 `update.ps1` 复制进任务目录并校验非空，`prepare()` 与 `handoff()` 都调用，旧任务目录重试也能补齐。
- `handoff()` 写 `launch.json`（token）、删除旧 `started.txt`/`ready`、按 token 判定心跳、保留 `HoYoMod-Recover.cmd`（先 Node 引擎，失败回退 PowerShell）。
- `app-update.ps1` 保持 0.9.9 原样（只在用户双击的恢复流程里有控制台可用）。

## Task 4：测试

- `tests/update-run.test.cjs`：替换/备份/回滚/`--recover-only`/受保护路径/链接拒绝/允许清单与 `app-update.cjs` 一致/等待父进程退出。
- `tests/update-helper.test.cjs`：心跳门控、宿主提前退出换引擎、无心跳换引擎、超时、全部引擎失败时的诊断路径。
- `tests/app-update.test.cjs`：`handoff()` 写 `launch.json`、复制引擎、写恢复脚本、按 token 判定心跳；旧任务目录重试补齐引擎文件。
- `tests/update-helper-windows.test.cjs`：真实 Windows 端到端（完整 Electron 运行时 + 无控制台 GUI 父进程 + 真实 Electron 宿主 + 真实 asar），验证助手存活、正在运行的 EXE 被替换、备份、data 保留与新版启动。

## Task 5：验证与产物

- `node scripts/check-syntax.cjs`、`node --test tests/*.test.cjs`。
- 推 `codex/` 分支触发 Windows CI，确认 Windows 变绿（当前为红，证据见 spec）。
- 版本升到 1.0.0，README 增加本版说明并同步下载文件名。
- 构建 Windows x64 ZIP，跑 `verify-windows-package.cjs` 与 `smoke-update-package.cjs`。
- 用户已授权：验证通过后打 `v1.0.0` 标签、创建 Release 并上传 ZIP 与 SHA256。
- 在 `docs/releases/1.0.0.md` 记录实际命令、结果与未验证项。
