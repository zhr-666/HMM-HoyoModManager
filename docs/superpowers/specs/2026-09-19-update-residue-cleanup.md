# 更新残留清理：软件更新包与模组安装包

## 已确认需求

用户报告：更新完成后更新包没有被删除，占用大量磁盘空间。确认对象包括两类（用户选择"两者都要清理"）：

1. 软件自身更新的临时目录 `.hoyo-updates/<任务 ID>`：`update.zip` 原包、`staging` 解包副本、`backup` 旧程序文件，每次更新约 1 GB，且**任何路径都不会删除它**。
2. 模组安装包 `data/downloads/<来源-文件>/package.zip`：安装成功后仍然保留，多个模组累积数百 MB 到数 GB。

## 现状

- `.hoyo-updates` 只在 `AppUpdate.init()` 中读一次 `current.json` 判定状态。更新成功后 `status.txt` 是 `complete`，`init()` 只提示"上次软件更新已完成"，不删除任何文件；`current.json`、`HoYoMod-Recover.cmd` 也留在程序目录里。每次更新产生一个新的 UUID 任务目录，因此是累积性泄漏。
- 下载/解包失败或用户放弃时留下的任务目录（没有 `status.txt`）同样永不清理。
- 模组安装成功后 `InstallService.install()` 只删除 `unpacked`，保留压缩包作为重试缓存（`history().cached`）；失败路径确实需要这个缓存（"重试不重新下载"是既有契约）。

## 方案

### 软件更新（`src/core/app-update.cjs`）

判定原则：**只要确认"更新已经生效"，就删除该任务目录**；无法确认时一律保留，保持现有恢复能力。

- `init()` 在原有状态判定之外收集"可清理任务"，并把实际删除交给后台任务（`this.cleanup`），不阻塞窗口出现；删除失败（文件被占用）不影响启动，下次启动会重扫。
- 判定为可清理的任务：
  - `status.txt` 为 `complete` 且 `plan.json` 的版本不高于当前运行版本（即替换确实生效）；
  - `status.txt` 为 `rolledback`（回滚已完成，暂存与备份都没有用途）；
  - `status.txt` 为 `pending` 且 `backup` 为空（助手从未开始替换），或目录里没有 `status.txt`（下载/解包中途放弃）；
  - 以上任一情况且不是本次会话的活动任务（`ready`/`recovery` 的任务不会被动）。
- 保留：`status.txt` 为 `updating` 的任务（替换途中中断，需要 `HoYoMod-Recover.cmd` 与 backup 恢复）、`pending` 且 `backup` 非空的任务、以及 `status.txt` 表明替换完成但运行版本仍低于计划版本的任务。
- 清理时同时移除 `current.json`（仍指向被清理任务时）与 `HoYoMod-Recover.cmd`（仅当本会话没有活动任务、且文件头确认是我们的恢复脚本）。
- `current.json` 指向的任务目录不存在时不再进入"需要恢复"死路：删除该指针并按空闲处理（用户手动删掉 `.hoyo-updates` 后仍能正常检查/下载更新）。
- 新增 `helper.lock` 进程存活检查：锁指向的进程还活着时不清理该任务目录。
- `_prepare()` 在解包与计划校验成功后立刻删除 `update.zip`（暂存已校验，后续重试用的是 `staging`），准备失败时删除本次新建的任务目录，避免同一会话内累积多个半成品。
- 手动覆盖更新（程序文件已是目标版本、记录停在替换开始前）的收尾改为同一套逻辑：登记该任务并在后台删除，不再"保留日志与备份"。
- `current.json` 指向的任务目录不存在、或记录里没有任何已替换的旧程序文件（`backup` 为空）时，不再要求用户恢复：替换尚未动过任何旧文件，记录无法也不需要恢复。
- 清理在有活动任务（`ready`/`recovery`）时保留恢复脚本；删除只针对本会话未使用的任务目录。

### 模组安装包（`src/core/install-service.cjs`）

- 安装成功后删除 `package.zip`（模组副本已经在 `data/library` 里，压缩包已无用途），并在记录里写入释放的字节数；删除失败不影响安装结果。
- 失败、取消、中断的记录仍保留压缩包，重试不必重新下载（既有行为不变）。
- 新增 `purgePackages()`：删除所有非进行中记录留下的安装包，返回 `{removed, freed, kept}`，用于清理本次改动之前遗留的安装包。

### 界面（`src/ui/index.html`、`src/ui/app.js`）

- 「下载」页页头新增「清理安装包」按钮，调用新的 `cleanupPackages` 操作，用提示条报告释放的空间；记录与模组本体不受影响，重试时会重新下载。
- 既有「清空全部记录」保持只清记录。

## 不做

- 不改 `data`、GIMI、本机库的保留规则。
- 不提供"从 backup 回滚到旧版程序"的新界面入口（备份只在更新未完成时用于恢复）。
- 不清理 `.hoyo-updates` 之外的任何程序目录内容。
