# 鸣潮与游戏列表管理

## 目标

在现有多游戏架构中加入鸣潮（`wuwa`，WWMI），让用户自行从「全部游戏」添加游戏到首页左侧栏。首次启动不预建任何游戏工作空间。旧用户已有的游戏数据和左栏入口保留。

## 行为

- 「全部游戏」始终显示支持的四款游戏。单击游戏将其加入左栏、选中并打开该游戏首页；双击继续进入工作空间。左栏新游戏出现在最下方，原图标向上移动。加入时才初始化 `data/games/<游戏 ID>`。没有已添加游戏时，首页内容区是纯灰背景，不显示背景图、Logo 或首页卡片，左栏「全部游戏」入口仍可用。
- 左栏游戏图标右键提供「移除游戏」。确认提示明确说明删除本机安装库、方案和设置，并清理该游戏启用库中的 `HoYoModManaged`。正在进行下载或操作时拒绝移除。清理失败则保留游戏登记和数据，允许重试。
- 对既有数据迁移时，按现有游戏顺序识别 `data/games` 中的有效游戏目录。升级后不删除旧数据，也不为未添加的新游戏创建目录。
- 鸣潮使用 GameBanana 游戏 ID `20357`、Skins 分类 ID `29524` 和 WWMI 启用路径。默认背景、图标和 Logo 随程序提供。「获取官方最新背景」先读取库洛启动器的当前背景配置，再下载官方首帧图片；失败时保留原背景。自动更新背景开关同样适用。
- GameBanana 分类树和「我的模组」的大分类中文显示使用同一套按 ID 映射；UI、缩写和专有名词保持原样。磁盘分类目录和安装记录不因翻译而迁移。
- 首页「管理我的模组」「管理搭配方案」复用进入工作空间的 Logo 飞行动画，并落到对应页面。

## 安全与验证

仅删除明确属于本程序的 `HoYoModManaged`；若同名目录无归属标记，停止删除并保留数据。用户选择其他启用子目录时，通过现有停用事务清除程序部署的模组。测试首次启动、旧数据识别、添加顺序、失败恢复、删除边界、鸣潮分类和入口动画。运行 `pnpm check`、`tests/ui-assets.test.cjs` 与相关界面脚本；Windows 实机更新验收留到发布前。
