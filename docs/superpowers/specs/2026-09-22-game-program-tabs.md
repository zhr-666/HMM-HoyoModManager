# 游戏独立的外部程序标签页

用户确认：每个游戏自行配置一级、二级 EXE；HMM 启动一级程序，一级程序启动二级程序，两个主窗口进入 HMM 顶部标签页。启用此功能要求 HMM 以管理员身份运行。关闭 HMM 时请求两级程序正常退出，不强制结束。使用 `feat/game-program-tabs` 分支。

## 行为与边界

- 复用 `launchExe` 作为一级路径，新增 `secondaryExe`、`programTabs`，三者按游戏隔离；旧配置保留，标签页默认关闭。
- 顶部保留 HMM 页，已接管窗口按游戏名和一级/二级显示。游戏切换不终止已启动会话；每个游戏只运行一个会话。
- 仅启动用户点击的一级 EXE，不主动运行二级 EXE。模组目录里的程序不能选择或启动。
- 接管条件为完整 EXE 路径、进程 ID 与创建时间，以及观测到的启动链。启动前已经运行的目标拒绝接管；同名但不同路径、无关新实例、PID 重用不能误接管。
- 原生窗口接口存在兼容性差异，不能承诺所有 EXE 可嵌入。失败恢复原有窗口样式和位置，给出通知；服务代理启动且无法证明归属的二级窗口保留独立状态。
- 二级关闭后再请求一级关闭。关闭请求未完成时取消 HMM 退出，目标恢复独立窗口并允许处理保存提示；再次点击打开程序可重新接管。绝不调用终止进程接口。软件更新交接之前执行相同检查。
- 原生弹窗保持独立以便处理保存、授权等操作；只嵌入无所有者的主窗口。
- Windows 助手通过标准输入输出 JSON 通信，加载随应用发布的固定 C# 源码，不拼接执行用户路径或参数，不新增 npm 依赖。退出/通信断开时尽力恢复被接管窗口。

## 验收

自动测试覆盖配置隔离及旧配置、管理员前置条件、完整路径和进程身份识别、启动失败、重复启动、嵌入失败恢复、退出取消及二级先关闭。界面验证覆盖两处游戏设置和顶部标签。运行 `pnpm check`、UI 缓存测试及相关界面冒烟。Windows 上额外验证真实一级→二级启动链、输入/焦点、多屏 DPI、主窗口重建、原生弹窗、取消关闭和更新退出。本机 macOS 不替代 Windows 实测，不打包发布、不升版本。
