# beta2 角色识别与悬浮窗修复

基准：v1.1.2beta2（19f5876，含后续发布记录 b958207）。用户已确认短暂识别失败保留展开窗口和上次角色，确认新角色后更新；叉号收回，游戏后台或退出隐藏。

## 行为

- 保留目标 EXE、Windows x64、主屏 1080p 的现有范围。未识别入口为半透明 Logo，识别后为同尺寸圆形不透明角色名；无鼠标悬停缩放或变色，仅指针变化。
- 点击入口，由入口所在圆形连续扩展为热键窗口；关闭反向收缩，结束后恢复入口。展开期间不重复显示入口。屏幕边缘向内展开，位置不跳回默认值。
- 左上标题和右侧角色名联合识别。使用已有角色字表约束 OCR；允许至少三字、首尾相同、仅一个中间字误读且候选唯一的修正，但必须两个区域共同支持。不对二字名作任意模糊匹配。
- 两区域精确一致时本帧确认；单区域精确命中或双方支持的修正连续两帧确认。切换角色仍验证；失配宽限 6 秒。展开窗口在 OCR 失配时保留，已确认另一角色时更新，即使没有热键也清楚显示空状态。
- OCR 异常与确认游戏退出/后台分开：异常报告一次并允许恢复，不将已显示窗口抹掉；没有已识别结果时显示 Logo。后台/退出立即隐藏并清空。
- 每轮按 350ms 目标周期调度，不叠加额外固定等待；捕获与 OCR 不重叠。前台检查只查询前台进程，不每轮扫描全部进程与窗口。
- 全圆可拖动，轻点展开。拖动过程中固定入口内容和尺寸，使用屏幕光标坐标计算偏移；位置及时更新，结束保存，不在拖动过程中重新应用旧坐标。

## 验证及约束

用户三张截图的文字裁区作为回归样本（不保存全图及 UID）。原 OCR 读出“干织”“革雨”“奥售塔”；记录改进后的真实结果。测试覆盖 OCR、歧义/误匹配、失配恢复、前后台、拖动/点击区别、动画与快速开关、设置保存失败和退出清理。执行 pnpm check、UI 缓存测试、Electron 悬浮窗冒烟。Windows 真游戏捕获、拖动、动画和升级后缓存另需实机验收。

不变更版本、不生成版本包、不发布。不更改模组文件、不新增依赖。
