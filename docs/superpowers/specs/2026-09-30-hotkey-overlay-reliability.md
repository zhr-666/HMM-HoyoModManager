# 原神热键悬浮窗可靠性与交互

## 目标

HMM 先于原神启动时，也能在游戏进入前台后自动识别。入口保持圆形，以现有 HMM 图标及其粉色底图填充，不绘制额外的黑色背景；没有可识别文字但游戏仍在前台时只显示图标。识别到已安装且有已启用热键或提示的角色后，在同一图标上显示角色名；其他非空文字继续显示图标。游戏退出、退到后台或屏幕不受支持时隐藏入口和详情。

## 识别与性能

- 游戏存在和前台状态使用专门的轻量探测，避免每轮为全部进程查询完整路径和枚举窗口。探测助手失败后自动重建，以免只能重启 HMM 才恢复。
- OCR 无文字时立即回到图标态，约每 3 秒取样；出现文字后沿用 2 秒快频率。连续两次确认角色，非空文字连续两次失配后回到图标态。整个取样过程不重叠。
- 原神工作区数据不依赖主界面当前选中的游戏；已启用的同一角色普通模组和皮肤模组的热键、提示都显示。

## 界面

- 入口继续为圆形透明窗口，图标铺满圆形；无额外深色底板、边框或黑色悬浮窗底色。鼠标悬停与拖动保持默认指针。拖动结束后保存位置；如果详情已打开则让详情跟随，越界位置需拉回工作区。拖动过程中不反复设置两个窗口尺寸。
- 详情右上角关闭按钮旁加齿轮按钮，点击切换热键列表和设置。默认显示列表。长热键提示允许换行，详情高度可按内容适当增加，并保持在屏幕内。
- 详情仅在热键数据变化时重建列表；设置变化只更新设置控件和字体，避免无谓布局与列表重绘。

## 验证

单元测试覆盖后启动游戏、探测失败恢复、空文字变速与入口状态、同角色多个已启用模组、拖动保存与详情设置。运行 `pnpm check`、`tests/ui-assets.test.cjs` 和悬浮窗冒烟测试。macOS 结果不能代替 Windows 1920×1080 游戏内拖动、透明度、更新后界面及全屏模式实测。
