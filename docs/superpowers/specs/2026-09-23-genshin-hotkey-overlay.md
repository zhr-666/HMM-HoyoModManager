# 原神角色热键悬浮窗

## 目标与范围

在 Windows x64 的原神 1920×1080 游戏画面中持续识别角色界面左上角的中文角色名。仅当识别名称对应当前原神工作区中的已启用模组，且该模组有热键或用户保存的热键提示时，显示一个可拖动的悬浮入口。点击入口展开置顶的热键小窗；关闭小窗后入口继续显示，直到识别条件消失。未识别或游戏画面不在前台时默认隐藏两个窗口。第一版不处理 2560×1440、其他游戏或英文名称。

## 识别与匹配

- 从主屏幕的实时画面取样，1080p 基准矩形为 x=215、y=28、宽=190、高=36，只覆盖左上角的斜杠与其后的角色名。宽度超过截图中当前角色名的两倍。按实际截图尺寸相对 1920×1080 缩放，以适应 1917×1079 一类的边缘差异；只在宽高接近 1920×1080 时运行。
- 单次取样与 OCR 不重叠；每 1500–2500 毫秒处理一帧。OCR 在本机完成，使用随包的简体中文数据，无网络调用，不写截图到磁盘。
- 斜杠必须位于识别结果开头，它只用于确认文字起点；匹配斜杠后面的角色名，不读取元素前缀。去除 OCR 插入的空格，优先匹配库中最长的已知中文角色名，以免长名字被误判为短名字；裁区右侧的少量 OCR 杂点不阻止匹配。至少连续两次匹配同一角色才显示，连续两次失配才隐藏；切换角色时要重新确认。
- 原神进程不存在时不捕获。游戏画面不在前台或截图无角色名时隐藏。不能把 HMM 自己的覆盖窗口纳入识别区域。
- OCR 初始化、捕获失败时关闭悬浮窗并报告一次易懂的错误；不影响主程序和游戏。

## 界面与设置

- 用两个透明、无边框的 Electron 窗口分别实现可拖动入口和可关闭的热键小窗。它们不嵌入游戏进程，不执行模组脚本。
- 入口显示当前角色名与“热键”标记。点击展开小窗；小窗展示该角色所有已启用模组的热键和用户保存的提示。无热键的模组不触发入口。
- 小窗提供入口大小、字体大小设置，保存至当前游戏的数据目录；入口位置在拖动结束后保存。设置范围与屏幕可用区域都要限制，避免窗口移出屏幕。
- 截图之外的画面和独占全屏能否覆盖，须在 Windows 实机验收。用户可改用无边框窗口模式。Windows 实机同时验证 1920×1080、游戏切换、退出与失败恢复。

## 项目约束与验收

- 沿用“安装”与“启用”术语；仅查询已启用的安装库副本，不改动 data 中的模组、GIMI 或手动文件。
- 新界面资源纳入 `UI_ASSETS`，通过 `hoyo://` 的 `no-store` 规则下发，并运行 `tests/ui-assets.test.cjs`。
- 添加 OCR 依赖时同步 `pnpm-lock.yaml`，随包附简体中文模型与许可说明；不修改版本号、不构建带旧版本号的新产物、不发布。
- 自动测试覆盖识别文字清理、模组匹配、稳定显示与隐藏、坐标换算及设置限制；运行 `pnpm check`。macOS 开发验证不能替代 Windows 捕获和覆盖窗口实测。

## 截图验证证据

用户提供的截图文件实际尺寸为 1917×1079。Tesseract.js 7.0.0 的简体中文识别在矩形 (215,28,190,36) 中识别出“/ 薇斯纳”；斜杠和角色名均在裁区内。单张静态截图仅证明识别区域与 OCR 方案可行。
