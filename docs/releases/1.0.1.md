# HoYoMod 1.0.1

日期：2026-09-17。状态：待 Windows 实机验收。源码标识：本次发布提交（提交号在发布后由后续记录补充，见文件末尾“发布提交”一栏）。

## 变更

### 启用/关闭模组改为逐条部署（修复误删同目录其他文件夹）

- 旧实现每次启用、关闭、同步模组都会清空并重建整个 `HoYoModManaged`，再把所有启用中的模组重新复制一遍。后果是关闭任意模组（尤其“全部关闭”）会连带删除 `HoYoModManaged` 下的 `BufferValues`、`Other/Misc`、依赖包以及用户手放的文件。
- 新实现按条目部署：每个模组对应一个条目目录 `HoYoModManaged/<Mod ID>`；选择了安装文件夹时对应 `<所选文件夹>/<Mod ID>`。启用只新增或替换这一个条目，关闭只移除这一个条目，其余文件夹一律不动。`HoYoModManaged` 根目录本身不再被重建。
- 归属判定：条目要么是指向本机库副本的链接，要么是带 `.hoyo-managed` 标记的真实目录；`HoYoModManaged` 根目录同样以 `.hoyo-managed` 标记归属。不属于本管理器的目录（例如其他管理器写下的 Mod ID 目录、`DISABLED ` 前缀目录）会被拒绝并提示，不会被覆盖。

### 启用模组改为创建快捷文件夹

- 启用时在 `HoYoModManaged/<Mod ID>` 创建指向本机库副本的真链接目录，不再复制文件；库中内容变化即时反映到 GIMI 加载目录。
- 同盘使用 Windows 目录联接（junction，免管理员权限）；GIMI 与程序不在同一磁盘时改用目录符号链接（symlink，需要开发者模式或管理员权限）。非 Windows 平台使用目录符号链接。
- 设置新增「用快捷文件夹启用模组」，默认开启；关闭后回到复制文件的行为。
- 说明：资源管理器的“快捷方式”是 `.lnk` 文件，3DMigoto 不跟随它，因此不使用 `.lnk`。

### 安装文件夹与子目录

- `HoYoModManaged/BufferValues`、`HoYoModManaged/Other/Misc` 这类子目录现在可以被选为安装文件夹（此前会被拒绝）；模组以链接形式装进该子目录。
- 仍拒绝直接选择 `HoYoModManaged` 根目录、`DISABLED` 前缀目录与 Mod ID 形态的目录。
- 修复选择尚不存在的安装文件夹时导入报 `ENOENT` 的问题（导入现在会创建所选文件夹）。
- 「打开 GIMI 中的目录」按新的部署路径解析，自定义安装文件夹的模组也能正确定位。

### 事务与恢复

- 部署事务日志升级为按条目的 v3 格式：暂存目录名 `__hoyo-staging-<uuid>`，单条目失败或断电只回滚受影响的条目。
- 0.9.9 及更早版本写下的“整目录重建”日志仍按旧规则安全回滚，升级后不会留下无法处理的残留日志。

## 更新失败时的恢复方法

退出 HoYoMod，把 1.0.1 完整解压覆盖到原程序目录，保留原 `data`、GIMI、Mods 及个人文件；不要删除原目录。0.9.9 及更早版本如果自动更新失败过，需按 README 中 1.0.0 的说明手动覆盖更新一次。
