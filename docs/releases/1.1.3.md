# HoYoMod 1.1.3

日期：2026-09-19。状态：**已发布，待 Windows 实机验收**。源码标识：`12220cc`（1.1.3 功能提交）、`de18def`（合并 `feat/update-residue-cleanup`）；本文件所在提交为 1.1.3 的版本提交，标签 `v1.1.3`。

## 变更

### 通知系统统一：只剩三种状态

- **3 秒即时通知**：按钮点成功后的即时反馈（「已加入下载列表」「开始检查更新」、忽略版本、更新官方背景、替换 Hash 完成、必填校验等），3 秒自动消失，不进通知中心、不计未读、没有关闭按钮、点不动。旧的下载小弹窗删除。
- **进行中的任务**：只出现在通知中心的「进行中的任务」区，不再主动弹窗；带「知道了」的任务弹窗与右下角任务堆栈整体删除。下载只挂**一张**队列卡，同一张卡里同时给出当前文件（文件名 + 百分比 + 进度条）与整个队列（「正在下载第 X 个，共 X 个」+ 总体进度条）；检查更新显示「正在检查更新第 X 个，共 X 个」。
- **完成 / 错误通知**：右下角常驻、不自动消失，只有「×」能关掉，关掉只是收起卡片，消息仍留在通知中心。「全部任务下载完成」「检查更新完成：…」、软件更新状态落到「发现新版本 / 已是最新 / 已准备好」都会补一条。
- 只有带对应页面的通知与任务卡才可点击（下载 → 下载列表，软件更新 → 设置里的软件更新卡片，检查结果 → 更新结果窗口），并显示手型。
- 页面上下的横条提示整体删除；错误仍是常驻通知，第一行是通俗中文，需要时展开「查看详细信息」看原始英文。

### 通知中心面板右上角的两个按钮（本轮复查后改的语义）

- 「×」＝**关闭通知中心小窗**，不删任何消息；重新打开面板消息仍在。
- 双勾＝**清空消息**（内部 id `notification-clear-all`，原「全部已读」）：清空消息历史，列表回到空状态、角标清零、`data/notifications.json` 同步清空；进行中的任务不受影响。展开面板时仍然自动把消息标记为已读，所以这个按钮不必再承担「标记已读」。
- 单条消息右侧的「×」仍然只删这一条。

### 下载可以取消，后台任务统一走 task-reporter

- 下载中与安装中的任务都能取消：立刻停下、清掉未完成的临时文件、状态记「已取消」（不是失败），之后还能重试；等待中的任务也能取消。
- `src/core/network.cjs` 的 `download` 支持外部 `signal`，中止不重试并清理 `.part*`；`install-service.cjs` 接收 signal，取消时记 `cancelled` 并清理临时文件。
- 后台任务抽到 `src/core/task-reporter.cjs`（节流推送、终态、取消回调），主进程用 `hoyo:tasks` 推给界面；下载队列的进度抽到 `src/core/download-progress.cjs`。

### 错误中文化与忽略版本

- 新增 `src/core/error-message.cjs`：`ENOENT/EPERM/ENOSPC/EACCES/EBUSY/EEXIST/ECONNRESET/ETIMEDOUT/ENOTFOUND/HTTP 4xx/5xx/fetch failed/校验失败` 等映射成通俗中文，原始信息随 `details` 给界面折叠显示，并写进 `data/logs/errors.log`。
- 新增 `src/core/ignored-updates.cjs`：检查更新结果窗口可以「忽略这个版本」（按具体版本而不是按模组），「我的模组」右键显示「已忽略版本：N 个」并可逐条取消。

### 游戏级设置（GIMI 路径、外部程序、启动器背景、XXMI 按游戏各存一份）

- 原神与其他游戏各自保存 GIMI 文件夹、外部程序、启动器背景与 XXMI 路径；1.1.2 及更早版本存在全局 `settings` 里的三个值在升级时整体迁移给《原神》，其他游戏留空。
- 新增「全部游戏」页（大图标网格 + 当前游戏设置）与游戏切换；首页右下角「打开程序」右边的齿轮打开当前游戏设置。数据迁移由 `src/core/library.cjs` 的 `normalizeGames` / `migrateGames` 完成，`tests/library.test.cjs` 覆盖迁移与隔离。

### 更新完成后的磁盘清理（并入 `feat/update-residue-cleanup`）

- 软件更新生效后删除 `.hoyo-updates/<任务 ID>`（原 ZIP、解包暂存、旧程序备份）并移除 `current.json` 与 `HoYoMod-Recover.cmd`；一次完整更新约 1 GB，此前每次都累加。需要恢复的未完成更新、替换途中中断仍可回滚的任务一律保留。
- 解包与计划校验通过后立即删除原 ZIP；准备失败不再留下半成品任务目录。
- 手动删掉 `.hoyo-updates` 后残留的更新记录在启动时作废，不再出现无法恢复的「请恢复旧版本」死循环。
- 模组安装成功后删除 `data/downloads/<来源-文件>/package.zip` 并提示「安装包已清理」；失败、取消与中断仍保留，重试不必重新下载。新增 `InstallService.purgePackages()` 与「下载」页的「清理安装包」入口，用来清掉此前遗留的安装包。

### 只保留深色模式

- 设置页删掉「外观主题」（浅色 / 深色 / 跟随系统）；界面、窗口底色（`#171a21`）与 Windows 标题栏按钮固定按深色取值，删除 `nativeTheme.on('updated')` 的主题重绘。
- `src/core/library.cjs` 的默认设置去掉 `theme`；旧 `settings.json` 里的 `theme` 读取时丢弃（不回写、不报错），旧界面缓存传上来的 `theme` 补丁被忽略而不是按未知设置项报错。
- `src/ui/style.css` 把原 `:root[data-theme="dark"]` 那套调色板搬进 `:root`，删除浅色变量与所有 `[data-theme]` 覆盖；`app.js` 不再写 `data-theme`，也不再监听系统深浅色变化。
- 顺带修掉浅色模式下「全部游戏」页的「当前游戏设置」卡片白底白字的问题——它随浅色模式一起消失。

### 游戏 Logo 飞行动画重做

用户反馈「就动画不对」。逐帧实测暴露三处问题，逐个修掉：

- 缓动 `cubic-bezier(.22,1,.36,1)` 在 14% 的时间就走完 74% 的距离，尾段 0.5 秒没有位移（看起来「先窜到终点再停住」）；改成 `cubic-bezier(.42,0,.22,1)`，720ms 不变，实测进度 200ms→13%、300ms→62%、500ms→89%、700ms→100%。
- `@keyframes game-icon-fly-back` 把起点/终点写反，导致返回首页时图标先瞬间跳到首页位置再往左栏顶端飞；删除该关键帧，进入与返回共用一组。
- 从「全部游戏」104px 大图标进入时飞行图层全程 104px、`x` 变负跑出窗口：终点改为「两个矩形中心差 + 按目标宽等比缩放」，实测 104 → … → 44.03 → 44，最小 `x=13.5`。
- 飞行期间目标位置的 Logo **与它所在方块的底色**一起隐藏，落点不再立着一块空的深色方块；最后一帧与目标逐像素重合后才交接（撤标记 + 用 0.16s opacity 过渡收掉飞行图层的投影），不再「先淡没、再突然出现」。
- 连点/双击会先取消上一次飞行，不会叠出两个 Logo；删除从未真正可见的 `rail-icon-land` 落地动画。

### 版本号说明

本次含多处兼容性功能变化（通知系统统一、取消下载、游戏级设置、深色专用），按 `docs/development.md` 的语义化版本意图本可升第二位；用户明确要求 1.1.3，故按 1.1.3 记录。1.1.2 → 1.1.3 没有不兼容变化：`data`、GIMI、模组库、搭配方案与已启用状态都不需要迁移；唯一的数据变化是旧 `settings.json` 里的 `theme` 字段被忽略。

## 更新失败时的恢复方法

退出 HoYoMod，把 1.1.3 完整解压覆盖到原程序目录，保留原 `data`、GIMI、Mods 及个人文件；不要删除原目录，也不要只替换 EXE。1.0.0 及更新版本可通过设置中的软件更新升级；0.9.9 及更早版本若自动更新失败过，需按 README 中 1.0.0 的说明手动覆盖更新一次。
