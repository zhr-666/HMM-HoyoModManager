# HoYoMod 1.1.0

日期：2026-09-18。状态：已发布，待 Windows 实机验收。源码标识：`ac319d4`（发布提交），标签 `v1.1.0`。

## 变更

### 启动器外壳：仿米哈游官方启动器的两级界面

- 启动后进入启动器首页：左侧窄栏自下而上为「设置」「全部游戏」与游戏图标。单击游戏图标＝选中并显示该游戏首页信息，双击＝进入该游戏的模组工作空间；工作空间侧栏顶部固定显示原神图标，单击返回启动器首页，工作空间侧栏不再有「首页」标签。
- 首页改为整屏铺满、不出现纵向滚动条：容量与当前方案贴在左下，齿轮与「打开程序」贴在右下，980×650 最小窗口下完整可见。
- 背景换为米哈游官方启动器的《原神》背景图（1920×1080 JPEG，随包内置），全局铺满所有页面；进入工作空间后背景模糊并叠加主题色遮罩，浅色/深色主题下卡片与列表文字保持可读。设置新增「获取官方最新背景」：从官方启动器公开接口 `hyp-api.mihoyo.com` 取当前《原神》背景并缓存为 `data/home-background.webp`；「选择图片」与「恢复默认」保留，恢复默认会同时清除官方缓存与自定义图片。
- 新增「全部游戏」页，列出当前管理的游戏；本次只有《原神》，界面与数据结构为以后接入其他游戏预留位置，不含其他游戏的适配逻辑。
- 图标从系统字体字符（✦ ▦ ◫ ⊞ ▱ ⌕ ▷ ☰ ↻ ⚙ × ↓）换成一套内联 SVG 线性图标：24×24 网格、1.6px 圆头圆角描边、`fill:none`、`stroke:currentColor`、尺寸 `1em` 跟随所在元素字号。14 个图标只在 `index.html` 的 `#i-*` symbol 表里定义一次，HTML 与脚本（`ICON()`、`dialog-stack.js`）都通过 `<use href="#i-*">` 引用。
- 可信来源新增 `hyp-api.mihoyo.com` 与 `launcher-webstatic.mihoyo.com` 两个主机，仅用于获取背景图；其余主机仍按原规则拒绝，相似域名与重定向仍被拒绝。

### 本机库文件夹：软件内选择存放位置与空白角色文件夹

- 「导入本地模组」拆成两步：`import` 只选压缩包并返回文件信息，`importApply` 先在软件内弹「选择存放位置」（按 GameBanana 分类逐层进入、可搜索当前层级、可为还没有模组的角色新建空白文件夹），确认后才解压、扫描前置并安装。GIMI 安装文件夹仍由系统对话框选择，部署行为不变。
- 「我的模组」新增「新建文件夹」入口；按角色创建的空白文件夹以文件夹卡片显示（0 个模组）并可进入，右键（仅空文件夹）提供「删除空文件夹」。文件夹里有模组、或目录里存在用户手放的文件时，界面不提供入口、核心层也会拒绝并说明原因。
- 选择弹窗使用完整 GameBanana 分类树（`buildLibraryPickerTree`）：分类即使还没有模组也会出现，模组数量与「已建文件夹」标记来自本机库；已登记但不在分类树里的文件夹也会补上，离线可用。
- 状态新增 `folders`：`{id, name, rootCategoryId, rootCategoryName, characterGroupId, libraryPath, createdAt}`，`init()` 校验后载入，无效项丢弃且不影响已有模组。库内相对路径沿用 `总分类-哈希/角色-哈希` 命名公式，因此「先建文件夹、后从 GameBanana 下载」一定落进同一目录，即使来源站返回的分类显示名与建目录时不同（`Library.install` 优先复用已登记文件夹的 `libraryPath`）。
- 手动导入到角色文件夹的模组写入真实分类编号，算作该角色并参与「同一角色只能启用一个」的互斥；未分类的本地导入仍为 `local:<uuid>`，各自独立。角色归属判定从「有 deploymentRelative 即非角色」改为按 `characterId` 前缀判定。
- 兼容性：本机库根目录位置（`data/library`）、库内目录命名与 GIMI 部署策略都不变，旧数据无需迁移；状态里没有 `folders` 时行为与 1.0.1 相同。

### 界面脚本与验收文档

- `scripts/smoke-*.cjs` 的页面跳转改为模式感知的 `gotoPage(name)`（按钮可见时点击，否则调用 `showPage`），适配新的启动器/工作空间两级结构。
- 新增 `scripts/smoke-library-folders.cjs`：通过 Electron 远程调试端口驱动真实界面，不依赖 Playwright。
- `docs/acceptance.md` 的首页章节重写为「启动器外壳与工作空间」，补充两级导航、整屏不滚动、官方背景与工作空间遮罩的验收步骤。

## 执行环境

- macOS 25.6.0（arm64），`/usr/local/bin/node` v24.21.0；electron 44.3.0、electron-builder 26.15.3，Windows 包复用缓存中的 `electron-v44.3.0-win32-x64.zip`。
- 本机 PATH 上的 `node` 是 DSH 提供的 Electron 垫片（`process.versions.electron` 有值、`node:fs` 带 asar 拦截），本记录的「本机」命令一律使用 `/usr/local/bin/node`。
- 本机文件沙箱默认只允许写工作区，而 `pnpm run` / `pnpm install` 需要写 `~/Library/Caches`、`~/Library/pnpm`；因此检查与构建改用等价命令直接调用同一份脚本与 electron-builder CLI：`node scripts/check-syntax.cjs`、`node --test tests/*.test.cjs`、`node node_modules/electron-builder/out/cli/cli.js --win zip --x64`（与 `pnpm pack:win` 同一目标、同一配置）。

## 更新失败时的恢复方法

退出 HoYoMod，把 1.1.0 完整解压覆盖到原程序目录，保留原 `data`、GIMI、Mods 及个人文件；不要删除原目录，也不要只替换 EXE。1.0.0 及更新版本可通过设置中的软件更新升级；0.9.9 及更早版本若自动更新失败过，需按 README 中 1.0.0 的说明手动覆盖更新一次。
