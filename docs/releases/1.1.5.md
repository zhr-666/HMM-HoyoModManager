# HoYoMod 1.1.5

日期：2026-09-20。状态：**本机构建完成，未发布**（用户本轮只要求升版本并打包 Windows 包做实机验收，未授权上传或创建 Release）。源码标识：本次改动仍在工作区，**尚未提交**（分支 `main`，基线 `0d40ddf`）；提交哈希待发布时补记。

## 变更与兼容性

修复 1.1.4 导入本地模组漏掉的一步：1.1.4 把导入简化成两步时，把渲染层的分类选择弹窗与主进程按分类解析落库位置的代码一起删掉了，压缩包交给本机库时不带分类，模组于是被当成未分类的本地导入，在「我的模组」最外层新建了一个「本地导入」总分类。

- 恢复「选择分类」弹窗：按 GameBanana 分类逐层进入（大分类 → 子分类/角色），**任意一层都能导入**（停在总分类上时安装库内只有一级目录，模组直接放进大分类），当前层级可搜索、面包屑可回退；确认按钮显示「导入到「<分类名>」」。
- `importApply` 重新接收分类编号：主进程 `resolveCategory` 先查已登记文件夹（离线可用），再查 GameBanana 分类树；缺少合法分类编号时直接报「请选择要导入的 GameBanana 分类。」，不再静默落到「本地导入」。
- 导入后的模组出现在「我的模组」所选分类的位置；安装库副本落在 `data\library\<总分类-哈希>[\<角色-哈希>]\<模组 ID>-<uuid>`；导入到角色分类的本地模组与工坊下载的模组同等对待（同一角色互斥、分类、启用/停用、检查更新、热键、重命名、移除）。
- 仍然不询问「Mods 内的安装文件夹」：启用位置自动进 `GIMI\Mods\HoYoModManaged\<模组 ID>`。取消或 ESC 关闭分类窗口则整个导入中止，不落库。
- 兼容性：`state.json` 结构不变，无需迁移；此前已落进「本地导入」的旧模组保持原样（不会自动搬家）。界面资源白名单未新增文件，`UI_ASSETS` 无需变化。
