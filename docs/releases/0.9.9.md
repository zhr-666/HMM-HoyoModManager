# HoYoMod 0.9.9

日期：2026-09-17。状态：已发布，Windows 实机验收待补。源码标识：发布提交 `a1ed9a3`，标签 `v0.9.9`。

## 变更

- 修复手动覆盖更新成功后，设置中持续提示「上次软件更新未完成，请恢复旧版本后重试」，且检查更新与下载更新都被拦住的问题。手动解压覆盖不会删除程序目录中的 `.hoyo-updates`，残留记录的 `status.txt` 仍是替换开始前写入的 `updating`，新版启动时把它当成未完成的更新。
- `AppUpdate.init()` 在该分支新增版本核对：读取残留记录 `plan.json` 的目标版本，不高于当前运行版本时判定替换其实已经完成，写入 `status.txt` 为 `complete`、删除 `current.json` 指针与本程序生成的 `HoYoMod-Recover.cmd`，保留任务目录中的日志、备份与暂存文件；目标版本更高或 `plan.json` 无法读取时维持原有恢复提示。`pending` 分支的判定与行为不变。
- 安装结构检查改为递归查找：从解压目录起，任意深度出现名为 `ShaderFixes` 的文件夹（不区分大小写）即拒绝安装，报错说明该文件夹需要放在 GIMI 根目录并提示手动安装。删除 `GIMI_ROOT_FOLDERS` 与「顶层 `mods` 之外还有其他文件夹」两条规则，`BufferValues` 与附带文件夹不再拦截。
- 「我的模组」的模组右键菜单新增「打开本机库」与「打开 Mods 文件夹」，分别打开该模组的库副本目录与 `GIMI/Mods/HoYoModManaged/<id>`。未启用的模组后者变灰并提示「此模组未启用，GIMI 中还没有它的文件。」。路径由主进程按模组 ID 计算，并校验仍在受管理目录内。
- 侧栏「设置」按钮移回最底部：删除折叠侧栏中覆盖 `.settings-nav{margin-top:auto}` 的 `margin-top:0`。
- 兼容性：部署方式、替换范围与数据结构均未改变，仍只替换程序运行文件并保留整个 `data`、启用组合、名称、搭配方案、GIMI 路径、外部程序和自定义背景。

### 构建环境说明

`pnpm check` 与 `pnpm pack:win` 未按原命令执行。本机 pnpm 在运行脚本前触发工具自身安装，向 `~/Library/pnpm` 写入被拒；改用等价的 `node scripts/check-syntax.cjs`、`node --test tests/*.test.cjs`。构建时 electron-builder 还会调用 `pnpm list` 收集依赖，pnpm 的 storeDir 记录在 `node_modules/.modules.yaml` 并指向 `~/Library/pnpm/store/v11/index.db`（工作区之外，只读），因此报 `ERR_SQLITE_ERROR: unable to open database file`；把该记录的 storeDir 临时指向可写目录后构建通过，构建结束后已还原。该文件属于 `node_modules`，不受版本管理，仓库内容未受影响。

## 更新失败时的恢复方法

旧版如果更新助手启动失败，请退出 HoYoMod，将完整 ZIP 解压覆盖到原程序目录，保留原 data、GIMI、Mods 及个人文件，不删除旧目录、不只替换 EXE。已经开始替换但未完成的更新，应先关闭 HoYoMod 并使用原更新目录对应的 `HoYoMod-Recover.cmd` 恢复，同时保留 `.hoyo-updates` 中的日志和备份。0.9.9 起，如果程序文件已经手动覆盖成新版，残留的更新记录会在启动时自动收尾，不再要求恢复。
