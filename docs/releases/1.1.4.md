# HoYoMod 1.1.4

日期：2026-09-19。状态：**已发布，待 Windows 实机验收**。源码标识：`ffce91f`（1.1.4 功能提交）、`e080ac9`（通知顶层定位修正）、`f656769`（合并 `feat/notification-ux-and-import`）；本文件所在提交为 1.1.4 的版本提交，标签 `v1.1.4`。

## 变更与兼容性

- 通知系统整块改用顶层（`popover="manual"`）：右下角通知弹窗、通知中心悬浮按钮与展开的面板永远画在对话框、遮罩与背景模糊之上；**位置不变**（仍是右下角），通知全部收完后自动离开顶层，不阻挡页面点击。
- 完成 / 错误通知改为弹出 8 秒后自动关闭，期间仍可点「×」提前关掉；消息与未读状态保留在通知中心。3 秒即时通知不变。
- 下载任务卡：整批只显示文字位置「正在下载第 X 个，共 X 个」，不再画整批的进度条与百分比；当前文件的进度条与百分比保留。
- 模组工坊翻页（上一页 / 下一页）在换页时立刻回到页面最上方，加载失败或取消也停在最上面。
- 导入本地模组只剩两步：选压缩包 → 选安装库分类 → 直接解压安装。不再弹出「选择 Mods 内的安装文件夹」；启用位置按其他模组同样的规则进 `GIMI\Mods\HoYoModManaged\<模组 ID>`。
- 移除随之失去入口的代码：`chooseLibraryFolder` / `buildLibraryPickerTree`、主进程的 `resolveCategory`、`categoryPath`、`createLibraryFolder`。本机库中已有的分类文件夹记录与模组不受影响，无需数据迁移。
- 界面资源缓存规则不变；`src/ui/*` 改动已同时更新，未新增界面文件，`UI_ASSETS` 白名单无需变化。

## 执行环境

macOS（开发机，Node 24.18.1 / Electron 44.3.0）。Windows 实机验收未进行。

## 检查命令与结果

- `pnpm check`（语法检查 + 全部单元测试）：312 个用例，310 通过、1 失败、1 跳过。唯一失败是 `tests/app-update.test.cjs` 的 “successful preparation…”，在**改动前的 main 分支上同样失败**（已用 `git stash` 对照确认），属本机环境问题（macOS 下 `fs.cp` 读取伪 `app.asar`），与本次改动无关。
- `node scripts/smoke-notifications.cjs`：通过（含 8 秒自动关闭与顶层断言）。
- `node scripts/smoke-library-folders.cjs`：通过（含两步导入、安装库路径、自动启用、`HoYoModManaged\<模组 ID>` 部署）。
- `node scripts/smoke-notification-layer-and-pager.cjs`（本次新增）：通过。像素对照显示对话框遮罩下通知面板亮度几乎不变（47 → 44），确认通知画在遮罩之上；工坊上一页 / 下一页都把滚动位置带回 0。
- 位置回归：开发中一度把 `[popover]` 的定位重置写成 `inset:auto`，导致悬浮按钮掉到左上角（实测 `left:0, top:0`）。已改为显式写回 `right:32px; bottom:32px` 并保持 `left/top:auto`；实测「带 popover / 不带 popover」逐像素一致（按钮 right 32 / bottom 32，矩形 `1171,724,46,46`），关闭态、有提示卡、面板展开三种状态都在右下角。`tests/notification-rules.test.cjs` 与冒烟测试各加了断言，禁止再出现 `inset:auto` 并核对几何。

Windows 实机结果：未进行。

未验证项与已知问题：

- Windows 实机上的顶层显示、8 秒自动关闭、翻页回顶与两步导入均未实测；macOS 上的 CDP 冒烟结果不能替代。
- 依赖 Playwright 的界面脚本（`smoke-workshop-navigation.cjs`、`smoke-renderer.cjs` 等）本次未运行：环境没有 Playwright（见 `docs/development.md` 的界面测试环境限制）。这些脚本未引用被删除的 `chooseLibraryFolder`，但其中翻页 / 滚动相关断言未经本次执行验证。
- 工坊翻页的冒烟验证在离线环境下进行：翻页动作与滚动回顶已验证，真实网络返回新一页内容的路径只做了代码层面的执行顺序断言。
- 既有打包缺口（本次发现，非本次引入）：`package.json` 的 `extraFiles` 里 `docs/acceptance.md → Windows验收说明.md` 与 `README.md → 使用说明.md` 两个中文名文件没有进 ZIP，1.1.3 的包同样没有这两个文件。不影响程序运行，待单独修复。
- 已知问题（既有，非本次引入）：macOS 上 `tests/app-update.test.cjs` 有 1 项失败（`fs.cp` 读取伪 `app.asar`），改动前的 main 分支同样失败；Windows CI 的既有失败见 1.1.3 记录。

更新失败时的恢复方法：与 1.1.3 相同（保留 `data` 目录与 `HoYoMod-Recover.cmd`）。
